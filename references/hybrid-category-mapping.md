# 品类融合项目：替换槽位映射方案

## 背景

当项目品类不直接匹配 shot_taxonomy.md 中 13 个固定品类中的任何一个时（如「RPG + 城池建设」「卡牌 + 模拟经营」「动作 + Roguelike」），不能直接查表获取替换槽位，需要按本规则组合生成。

## 映射规则

### 步骤一：拆分项目为玩法组件

将项目拆分为 1-2 个核心玩法组件。每个组件应能在品类映射表中找到对应。

示例：「像素三国RPG + 轻城池建设」
- 组件 A：RPG 角色驱动（武将收集、养成、编队）
  → 映射「二次元角色驱动」→ 替换槽位候选：多角色合影 KV、抽卡界面、角色三视图
- 组件 B：城池建设/资源经营
  → 映射「模拟经营」→ 替换槽位候选：经营全景俯视、装饰/家园、订单/任务

### 步骤二：按优先级选 2-3 张

选槽位逻辑：
1. 选最能体现**玩法融合独特性**的槽位（至少 1 张）：该画面能直观展示"这不是单一品类游戏"
2. 选**核心玩法高频画面**：用户每分钟都在看的东西
3. 选**传播性画面**：截图就能让人想玩

从组件 A 和 B 的候选槽位中交叉选取，优先挑能同时体现双玩法的画面。

### 步骤三：自定义槽位命名

不要照搬品类映射表的槽位名。根据项目实际玩法重命名，使 slot 描述对后续 M5 prompt 生成有直接指导价值。

| 错误 | 正确 |
|------|------|
| 经营全景俯视 | 城池建设俯瞰（含武将驻防） |
| 抽卡界面 | 武将招募系统（名将转盘） |
| 装饰/家园 | 城内交互场景（资源+居民） |

### 步骤四：检查社交槽位触发

仅当两个组件都命中社交驱动标签时才启用 S10。杂交品类默认不启用，除非用户明确要求社交系统是核心玩法一部分。

## 实例：本会话项目

项目：像素三国RPG + 轻城池建设（C1）

| 槽位 | 来源组件 | 命名 | 体现融合？ |
|:----:|:--------:|------|:---------:|
| S7 | 模拟经营→城建俯瞰 | 城池建设俯瞰 | ✅ 直接展示城建核心玩法 |
| S8 | 二次元角色驱动→抽卡 | 武将招募系统 | ✅ 展示 RPG 养成入口 |
| S9 | 自定义组合 | 城内交互场景（资源+居民） | ✅ 展示城内经济循环，差异化于纯RPG |

社交槽位：❌ 不启用

## 注意事项

- 当项目有 3 个以上玩法组件时，只取前 2 个权重最高的，避免槽位散焦
- 「RPG + 城建」→ S7/S8/S9 的分配是通用模板：城建(差异展示) + 招募(核心循环) + 城内(深度展示)
- 换品类组合时调整模板即可
